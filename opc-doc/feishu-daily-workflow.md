## 2. 任务字段标准（可执行闭环）

每项任务、交接或待办**必须**包含以下字段，缺一不得进入「进行中」：

| 字段 | 说明 | 示例 |
| --- | --- | --- |
| **负责人** | 当前执行人 | Brian |
| **截止日** | 可验收日期 | 2026-08-05 |
| **预期输出** | 交付物名称 + 数量/规格 | 3 套 Amazon 主图对比卡，1080×1080 PNG |
| **下一位接手者** | 完成后谁确认/接手 | Howard 客户确认 |
| **完成标准** | 怎样算 Done | 客户可在飞书预览并通过，或 Howard 标记「可外发」 |
| **关联资料** | 文档库或本站链接 | `product-spec-and-pricing.md` §体验包 |
| **状态** | 待办 / 进行中 / 待确认 / 被阻塞 / 已完成 | 待确认 |

### 默认视图规则

- **当前待办**：状态 = 待办 或 进行中，负责人 = 我
- **待我确认**：下一位接手者 = 我，状态 = 待确认
- **被阻塞**：状态 = 被阻塞（晨会必须读出阻塞原因与解除条件）
- **历史**：通过日期或状态筛选，不进入首页

## 4. 线索与订单推进

```
触达/回复 → T05 新建询盘 → 需求诊断 + 报价（T10 / 本站计算器）→ 50% 订金
    → T01 派单给 Brian → 交付 → T08 案例沉淀 → T06 复盘成交路径
```

询盘状态建议：`新询盘` → `需求确认` → `已报价` → `已付订金` → `交付中` → `已结案` → `流失`。

## 5. 与 GitHub Pages 的边界

| 放在飞书 | 放在 GitHub Pages |
| --- | --- |
| 任务状态、负责人、截止日 | 任务字段定义与本 SOP |
| 线索跟进、成交金额 | 报价标准、案例、平台规范 |
| 晚间复盘、次日 Top 3 | 复盘四问模板、晨会议程 |
| 案例包装进度 | Demo 展示与 Prompt 参考 |

**禁止**：在浏览器 localStorage、本机 `app.js` 或 Pages 表单中维护「权威」任务/线索状态。

## 6. 配置入口

1. 在飞书创建多维表格并导入 `feishu-import/*.csv`。
2. 将 base 链接写入 `portal/site-config.json` → `feishu.baseUrl` 及各表 `path`。
3. 运行 `python3 build_opc_html.py` 重新生成首页飞书跳转按钮。
